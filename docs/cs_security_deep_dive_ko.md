# CS 및 암호학/네트워크 보안 심화 분석 (Deep Dive)

본 문서는 FIDO2 소유권 증명(PoP) 아키텍처의 기반이 되는 암호학, 네트워크 보안, 시스템 설계 원리를 패킷과 메모리 수준에서 분석한다.

## 1. 비대칭키 암호화 및 디지털 서명 (ECDSA P-256 vs RSA)

### 타원곡선 암호(ECC)의 원리와 P-256 선택 배경

RSA 알고리즘은 두 소수의 곱을 소인수분해하는 계산적 난해함에 의존한다. 반면 타원곡선 암호(ECC)[10]는 유한체 위의 타원곡선 이산 대수 문제(ECDLP)를 기반으로 한다.

본 시스템이 NIST P-256 (secp256r1)을 채택한 이유는 두 가지이다[6].

1. **키 길이 효율성**:
  RSA에서 128비트 보안 강도를 얻으려면 3,072비트 키가 필요하지만, ECC는 256비트 키로 동일한 보안 수준을 달성한다.
2. **전송 오버헤드 절감**:
  서명 데이터 크기가 약 64 Bytes에 불과하여, 매 HTTP 요청 헤더에 서명을 첨부하는 PoP 아키텍처의 네트워크 페이로드를 크게 줄인다.

### 서명 생성(Sign)과 검증(Verify)의 수학적 흐름

1. **생성(Sign)**:
   클라이언트는 임의의 난수 $k$를 선택하고 타원곡선 연산으로 점 $(x_1, y_1)$을 구한다. 이후 메시지 다이제스트(SHA-256) $z$, 개인키 $d$, $x_1$을 이용해 서명값 $(r, s)$를 계산한다. 이 두 값은 Base64로 인코딩하여 HTTP 헤더에 포함한다.
2. **검증(Verify)**:
  게이트웨이는 서명 $(r, s)$, 원본 메시지 해시 $z$, 그리고 송신자의 공개키 $Q$를 수신한다. 매개변수 $u_1, u_2$를 계산한 뒤, 기준점 $G$와 공개키 $Q$를 선형 결합하여 $R' = u_1 \cdot G + u_2 \cdot Q$를 도출한다. 이는 이산 대수의 역산이 아닌 정방향 연산이다. 최종적으로 $R'$의 x좌표 $x_{R'}$이 $r$과 법 $n$에 대해 합동($x_{R'} \equiv r \pmod n$)이면 서명 유효성을 승인한다.

## 2. HTTP 요청 정규화 (Canonicalization)와 무결성 보장

토큰 자체에만 서명하면 공격자가 탈취한 서명을 다른 엔드포인트 호출이나 변조된 페이로드에 재사용할 수 있다[9]. 중간자 공격(MitM)을 차단하기 위해 HTTP 요청의 핵심 필드를 단일 바이트 문자열로 결합하여 정규화한다.

### 파이프라인 구조
```text
SigningPayload = HTTP_METHOD | URI_PATH | SHA-256(BODY) | NONCE | TIMESTAMP
```

### 스트리밍 처리와 메모리 복잡도

SigningPayload에 본문 원본 대신 SHA-256(BODY) 다이제스트를 사용하는 것은 메모리 관리를 위한 의도적 설계다.

게이트웨이는 대용량 페이로드를 업스트림으로 전달할 때 청크 단위 스트리밍(Chunked I/O)을 사용한다. 본문 원본을 정규화 문자열에 직접 결합하면 서명 검증을 위해 전체 페이로드를 게이트웨이의 RAM(단일 메모리 버퍼)에 모두 적재해야 한다. 반면 다이제스트를 사용하면 네트워크 스트림을 통과시키면서 hasher.update(chunk) 호출로 해시를 점진적으로 누적한다.

결과적으로 검증 계층에서 발생하는 부가적인 메모리 할당량을 SHA-256 다이제스트 크기인 32 Bytes로 고정하여 공간 복잡도를 $O(1)$로 유지한다.

💡 [심화 개념: 길이 연장 공격 방어 및 제로 카피(Zero-Copy) 최적화]
  단순 해시 함수(SHA-256 등)는 해시값 뒤에 임의의 데이터를 덧붙이는 '길이 연장 공격(Length Extension Attack)'에 취약할 수 있다. 그러나 본 아키텍처는 해시된 다이제스트를 최종적으로 개인키 기반 비대칭 서명(ECDSA)으로 감싸기 때문에, 공격자가 페이로드 길이를 임의로 조작하더라도 수학적으로 원천 차단된다. 또한 스트리밍 해시 처리 시 OS 레벨의 sendfile() 체계나 제로 카피 아키텍처를 연계하면 애플리케이션 계층의 컨텍스트 스위칭 오버헤드를 극단적으로 낮출 수 있다.

## 3. 재전송 공격(Replay Attack) 방어 및 이중 DoS 방어

게이트웨이는 일회용 난수(Nonce)와 타임스탬프를 조합하여 서명된 패킷의 재전송 공격을 방어한다[7]. 그러나 난수 발급 엔드포인트(/auth/nonce) 자체가 서비스 거부(DoS) 공격의 표적이 될 수 있으므로 두 가지 방어 계층을 병행한다.

### 3.1. L7 Ingress Flooding Mitigation (단기 폭증 방어)

봇넷이 인증 없이 Nonce 발급 요청을 쏟아내어 CPU와 네트워크 자원을 소진시키는 볼류메트릭(Volumetric) 공격에 대응한다.

클라이언트 IP를 키로 삼아 슬라이딩 윈도우(Sliding Window) 알고리즘으로 요청 빈도를 추적한다. 단일 IP가 초당 10회를 초과하면 즉시 429 Too Many Requests와 Retry-After: 1 헤더를 반환하고 연결을 종료한다. 이후의 암호 연산 로직은 실행하지 않는다.

### 3.2. State Accumulation Prevention (장기 상태 누적 방어)

정상적인 속도로 Nonce를 발급받은 뒤 실제 요청에 사용하지 않으면 게이트웨이 메모리에 미사용 상태가 누적된다. 시스템은 이를 세 가지 방식으로 제어한다.

1. **스레드 안전성(Thread-Safety)**: threading.Lock()을 사용하여 멀티스레드 환경의 동시 접근을 제어하고 경쟁 상태(Race Condition)를 방지한다.
2. **슬라이딩 윈도우 TTL (60초)**: 발급된 모든 Nonce에 60초의 생명주기(TTL)를 부여한다.
3. **가비지 컬렉션(GC)**: 만료된 항목을 주기적으로 순회하여 삭제한다. 60초가 지난 타임스탬프를 가진 요청은 캐시 조회조차 수행하지 않고 선제 기각한다.

💡 [심화 개념: 분산 환경에서의 원자적 제어(Atomic Control) 및 경합 조건]
  단일 노드에서는 threading.Lock을 통한 상호 배제(Mutex)가 유효하지만, 게이트웨이가 다중 인스턴스로 수평 확장(Scale-out)되면 로컬 메모리 락은 효력을 상실한다. 이 경우 난수 저장소를 Redis와 같은 분산 인메모리 스토어로 이관해야 한다. 특히 공격자가 동일한 Nonce를 가진 유효 요청 2개를 마이크로초 단위로 동시에 전송하는 TOCTOU(Time-of-Check to Time-of-Use) 공격을 막기 위해, 단순 '조회 후 삭제(GET then DEL)'가 아닌 Redis Lua Script 기반의 원자적 연산(Atomic Compare-and-Delete)을 적용해야 동시성 결함을 히 해결할 수 있다.

## 4. FIDO2 / WebAuthn 하드웨어 바인딩의 특성

FIDO2 규격[4][5]은 개인키를 호스트 OS 메모리에 노출하지 않고 하드웨어 수준에서 격리한다. 이는 DPoP[2]와 같은 소프트웨어 기반 키 관리 모델과 대비되는 핵심 차별점이다.

### OS 및 보안 모듈과의 통신 흐름

1. 클라이언트(웹 브라우저)가 JavaScript navigator.credentials.get() API를 호출한다.
2. 브라우저는 OS의 WebAuthn 구현체(Windows Hello, macOS TouchID 등)로 제어를 위임한다.
3. OS는 서명 챌린지(Challenge)를 신뢰 플랫폼 모듈(TPM)[8], 모바일의 보안 엔클레이브(Secure Enclave), 또는 외장형 YubiKey(CTAP2 프로토콜) 중 해당 하드웨어로 전달한다.

### 추출 방지(Anti-Exfiltration) 설계

공격자가 OS 커널 권한을 탈취하거나 브라우저 제로데이 취약점을 악용하더라도 개인키 자체는 유출되지 않는다.

보안 칩은 외부에서 챌린지를 수신하여 내부 논리회로에서 서명 연산을 수행한 뒤, 결과값(Signature)만을 외부 버스로 반환한다[8]. 애초에 하드웨어 명령어 셋(Instruction Set)에 칩셋 내부의 개인키를 메모리로 읽어내는(Read-out) 명령어 자체가 존재하지 않기 때문이다.

💡 [심화 개념: 하드웨어 신뢰 근원(Root of Trust)과 물리적 차폐]
  TPM이나 Secure Enclave와 같은 보안 프로세서는 메인 CPU 및 RAM과 분리된 독자적인 연산 환경을 갖는다. 이를 '신뢰 근원(Root of Trust)'이라 부른다. 이 칩셋들은 물리적인 탬퍼링(회로 기판 분해, 전압 강하 등)을 감지하면 내부 저장 키를 즉시 파기하는 '탬퍼 레지스턴스(Tamper Resistance)' 설계가 적용되어 있다. 따라서 커널 레벨의 메모리 덤프(RAM Dump)나 콜드 부트(Cold Boot) 공격과 같은 호스트 기반 침해 기법이 원천적으로 통용되지 않는다.
